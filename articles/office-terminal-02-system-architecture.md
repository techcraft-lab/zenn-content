## はじめに

前回の記事では、事務所の日常点検と社員の在席管理を行うWebアプリ「office_terminal」について紹介しました。

そもそものきっかけは、「事務所の点検簿を電子化すれば、記録も残せるし便利になるのでは？」と、ふと思ったことでした。

最初から大がかりなシステムを作ろうと考えていたわけではありません。

ただ、せっかく作るのであれば、身近な業務を少し便利にするだけでなく、若手社員が「自分たちでもこんなものが作れるんだ」と、ものづくりに興味を持つきっかけにもなればと思いました。

今回は、手元にあったPCやRaspberry Pi、古いタブレットを活用しながら、どのような構成に落ち着いたのか、その試行錯誤も含めて紹介します。

## 1. きっかけはWindows 11にアップグレードできなかったPC

今回の開発とは少し別の話になりますが、以前からWindows 11にアップグレードできないPCが何台か手元にありました。

Windows 10のサポート終了もあり、これらのPCをどう活用するか考えていたところでした。

まだ十分に動作するPCを、そのまま使わなくなるのはもったいない。

そこで、Linuxをインストールすれば、何か面白いことに活用できるのではないかと考えました。

その中の1台が、Lenovo ThinkCentre M715qという小型PCです。

このPCにUbuntu Server 24.04 LTSをインストールして、自宅でいろいろ試してみることにしました。

Ubuntu Serverは、一般的なWindowsのようなデスクトップ画面を持たないCUI環境で構築しています。

最初は少し扱いにくいのではないかと思いましたが、SSHを使用すれば別のPCから操作できます。

普段使用しているWindows PCからVS Codeで接続し、プログラムの編集や実行ができる環境を用意しました。

この環境を使って、今回のオフィス管理システムの開発を進めることにしました。

## 2. 開発環境と運用環境を分ける

現在は、自宅の開発環境とオフィスの運用環境を分けています。

基本的な開発や動作確認は自宅のM715qで行い、ある程度完成したプログラムをオフィスのRaspberry Piへ移設する方式です。

![開発環境と運用環境のシステム構成図](/images/office-terminal/system-architecture.png)

システム構成をまとめると、次のようになります。

| 項目 | 開発環境 | 運用環境 |
| --- | --- | --- |
| 設置場所 | 自宅 | オフィス |
| ハードウェア | Lenovo ThinkCentre M715q | Raspberry Pi 3B |
| OS | Ubuntu Server 24.04 LTS | Raspberry Pi OS Lite |
| 画面環境 | CUI | CUI |
| 主な役割 | 開発・テスト | Webサーバー・データ保存 |
| 管理方法 | Windows PCからSSH接続 | SSH接続 |
| 操作端末 | PCのWebブラウザ | タブレット中心 |

オフィスでは、Raspberry Pi 3BがWebサーバーとして動作し、同じネットワークに接続したタブレットからアクセスします。

アプリケーションの処理やデータの保存はRaspberry Pi側で行い、タブレットは操作画面として使用します。

この方式なら、タブレット側に専用のプログラムを組み込む必要がありません。

Webブラウザからアクセスするだけなので、PCやスマートフォンからも利用できます。

また、開発環境と運用環境を分けておくことで、自宅で新しい機能を試したり、動作を検証したりしながら、オフィス側のシステムを維持できます。

## 3. Raspberry Pi 3Bでも十分に動作した

開発にはM715qを使用していますが、オフィスでの運用には、以前から手元に余っていたRaspberry Pi 3Bを使用することにしました。

Raspberry Pi 3Bは、現在では決して高性能な機種ではありません。

ただ、今回のシステムが行うのは、主に次のような処理です。

- 日常点検の記録と表示
- 社員の出退勤・在席状態の管理
- カレンダーや履歴の表示
- SQLiteへのデータ保存
- タブレットやPCからのアクセス

高度な画像処理や大量のデータ処理を常時行うわけではありません。

そこで、まずは手持ちのRaspberry Pi 3Bで試してみることにしました。

すると、予想していた以上に普通に動作しました。

M715qとRaspberry Pi 3Bではハードウェアの処理能力に大きな差がありますが、今回のWebアプリを操作する範囲では、体感的な速度の差をほとんど感じませんでした。

もちろん、これは今回の用途での話であり、両者の処理性能が同等という意味ではありません。

それでも、比較的小規模なWebアプリであれば、古いRaspberry Piでも十分に活用できることが分かりました。

### OSはRaspberry Pi OS Liteを採用

Raspberry Pi 3Bには、GUIを持たないRaspberry Pi OS Liteをインストールしています。

今回のシステムでは、画面表示やタッチ操作はタブレット側で行うため、Raspberry Pi本体にデスクトップ画面は必要ありません。

Raspberry Pi側はWebサーバーとしての処理に専念させる構成です。

また、SSHで管理できるため、通常の運用ではRaspberry Piにモニターやキーボードを接続する必要もありません。

古い機器を使用するからこそ、できるだけシンプルな環境で動かすことを意識しました。

## 4. 5インチタッチパネルで開発を始めたものの……

表示端末についても、開発途中で大きく方針を変更しました。

当初は、手元にあった5インチのHDMIタッチパネルディスプレイを使用するつもりでした。

解像度は800×480です。

このディスプレイを前提に、画面のレイアウトや操作ボタンなどを設計していました。

しかし、実際に完成に近づいた画面を表示してみると、問題が出てきました。

**5インチでは、思っていた以上に画面が小さかったのです。**

点検項目を選択するだけなら何とかなりますが、今回のシステムでは現在の出社者一覧、日付や時刻、天気情報なども表示したいと考えていました。

それらを限られた画面に収めると、どうしても窮屈になります。

文字やボタンの大きさ、視認性、操作性を考えると、もう少し大きな画面が欲しくなりました。

![当初使用予定だった5インチタッチパネル](/images/office-terminal/display-5inch.png)
5インチディスプレイでの表示イメージやサイズ感が分かりやすいように、home画面を合成したイメージ写真を作成してみました。

### 大きなタッチパネルを探してみた

そこで、もう少し大きなタッチパネルモジュールを探すことにしました。

10インチ程度あれば、表示もかなり見やすくなりそうです。

ただ、調べてみると、タッチ対応のディスプレイモジュールは意外と高額でした。

ディスプレイを大きくするだけのために、そこまで費用をかけるべきか少し迷いました。

もともと手持ちの機器を再利用するところから始めた取り組みです。

できれば、あまり費用をかけずに実現したいと考えていました。

## 5. 古いタブレットが意外と使える

何か代わりになるものはないかと考えていたところ、以前使用していた古いタブレットがあることを思い出しました。

性能的にはかなり古い機種ですが、今回の用途なら高速な処理は必要ありません。

試しにブラウザからWebアプリを開いてみたところ、十分に利用できそうでした。

さらに、キオスクモードに対応したブラウザアプリを使うことで、アドレスバーなどを表示せず、専用端末のように画面を表示できることも分かりました。

キオスクモードとは、特定のWebページなどを全画面で表示し、専用端末のように使用するための機能です。

結果として、当初考えていた小型ディスプレイを使う方式よりも、すっきりした構成になりました。

![採用したタブレットとRaspberry Pi 3B](/images/office-terminal/tablet-raspberrypi.png)

### Wi-Fi接続には大きなメリットがあった

タブレットを採用したことで、もう一つ大きなメリットがありました。

Wi-Fiで接続できるため、基本的に必要な配線は充電用の電源だけです。

HDMIケーブルやUSBのタッチ入力用ケーブルなどを接続する必要がなくなりました。

また、タブレットなので、固定した場所だけで使用する必要もありません。

今回のシステムには日常点検簿の機能があります。

エアコン、窓の施錠、電灯、電気機器などを確認する際に、タブレットを持ち歩きながら点検結果を入力できます。

当初は固定式の操作端末を考えていましたが、結果的には持ち運べるほうが使い勝手がよい場面もありそうです。

実際に試してみると、最初に考えた構成が必ずしも最適とは限らないことを感じました。

## 6. ソフトウェアと開発環境

今回使用している主なソフトウェアは次のとおりです。

| 項目 | 使用技術 |
| --- | --- |
| 開発用OS | Ubuntu Server 24.04 LTS |
| 運用用OS | Raspberry Pi OS Lite |
| プログラミング言語 | Python |
| Webフレームワーク | FastAPI |
| データベース | SQLite |
| 画面 | HTML / CSS / JavaScript |
| 開発ツール | VS Code |
| リモート接続 | SSH |
| ソースコード管理 | Git / GitHub |
| Python環境管理 | uv |

実は、これらのソフトウェアを最初から詳しく理解して選定したわけではありません。

「こういうことを実現したい」という内容をAIと対話しながら整理し、必要な技術や構成を決めていきました。

プログラムの作成にもAIをかなり積極的に活用しています。

自分で実現したい機能や動作を考え、AIと相談しながら仕様を具体化し、実際に動かして確認するという進め方です。

この開発方法については、今回の記事だけでは説明しきれないため、別の記事で詳しく紹介したいと考えています。

今回は、こうした技術を組み合わせてシステムを構築した、という紹介にとどめます。

## 7. GitHubとuvを使ってRaspberry Piへ移設

自宅のM715qで開発したプログラムは、GitHubでソースコードを管理しています。

オフィスのRaspberry Pi 3Bへ移設する際にも、この仕組みを活用しました。

Pythonの実行環境については、uvを使用しています。

uvはPythonのパッケージや実行環境を管理するためのツールです。

開発用PCとRaspberry PiではCPUの種類や環境に違いがありますが、GitHubによるコード管理とuvによるPython環境の構築を利用することで、移設作業は思っていた以上にスムーズに進みました。

もちろん、最初からすべてを理解して設定できたわけではありません。

ここでもAIと対話しながら、一つずつ確認して環境を整えていきました。

最終的には、Raspberry Piの起動時にWebアプリが自動起動するところまで設定できました。

これで、オフィスに設置して使用するための基本的な環境が整いました。

具体的な環境構築や自動起動の設定方法については、別の記事で紹介したいと思います。

## 8. オフィスに設置して試験運用へ

現在は、Raspberry Pi 3Bとタブレットをオフィスに設置し、試験運用を行っています。

Webアプリの基本機能や自動起動の動作も確認できました。

ただし、実際に社員が日常的に使用する中では、これまで気づかなかった問題が出てくるかもしれません。

画面の操作性や表示内容、運用上の細かな改善点などは、今後も見直していく予定です。

まずは実際に使える状態にして、使いながら改善していく。

今回は、そんな進め方でもよいのではないかと考えています。

## 9. 小さな思いつきから、ものづくりのきっかけへ

今回のシステムは、「点検簿を電子化したら便利なのでは？」という小さな思いつきから始まりました。

特別な機器を揃えたわけでもなく、使わなくなったPCや余っていたRaspberry Pi、古いタブレットを組み合わせて作ったものです。

それでも、実際の業務で使えるシステムとして形にすることができました。

現在は試験運用を始めたところですが、これから社員に使ってもらう中で、いろいろな意見が出てくると思います。

特に若手社員には、

「ここをもう少し改善したい」

「こんな機能を追加できないだろうか」

といった興味を持ってもらえれば嬉しいです。

そして、そうした小さな気づきから、自分で考え、試して、形にしていくことの楽しさを感じてもらえればと思っています。

最初から立派なシステムを作る必要はなく、身近なちょっとした不便を改善することも、十分にものづくりのきっかけになります。

今回の取り組みが、日々の業務改善につながるとともに、若手社員がものづくりの面白さを感じる一つのきっかけになればと思っています。
